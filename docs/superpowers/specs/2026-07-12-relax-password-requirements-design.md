# 放宽密码设置限制设计

## 目标

允许所有账户使用任意非空密码，包括字面值 `zhang...`。移除现有的 12 字符最低长度限制，同时保留必要的表单一致性检查。

## 范围

- 首次登录后的强制改密流程允许任意非空新密码。
- 账户设置中的主动改密流程允许任意非空新密码。
- 邀请激活与管理员重置普通用户密码时同样采用“只要求非空”的统一规则。
- 前端提示、HTML 属性和按钮可用条件与服务端规则保持一致。

不在本次范围内：修改现有账户密码、部署到服务器、调整密码哈希算法、取消两次密码确认或取消当前密码验证。

## 行为规则

1. 新密码为空时拒绝提交，并返回清晰的中文错误信息。
2. 新密码为任意非空字符串时通过密码强度校验；`zhang...` 必须可用。
3. 改密时仍要求当前密码正确。
4. 两次输入仍必须一致。
5. 主动改密与首次强制改密仍不允许新密码和当前密码相同。
6. 密码继续使用现有 scrypt 哈希存储，不记录或展示明文。

## 实现边界

服务端认证与用户管理逻辑作为最终校验边界，移除 12 字符判断并改为非空判断。相关 React 表单移除 `minLength={12}`、长度提示和基于 12 字符的禁用条件，改为仅在新密码非空时允许提交。所有入口共享相同语义，避免浏览器校验与服务端结果不一致。

## 测试与验收

- 先增加失败测试，证明现有代码拒绝 `zhang...`。
- 修改后验证首次改密能将密码设为 `zhang...`，旧密码失效，新密码可登录，强制改密标记被清除。
- 验证空密码仍被服务端拒绝。
- 更新受影响的用户管理测试，并运行相关测试、lint 和生产构建。
- 不在测试输出、日志或审计摘要中写入密码明文。

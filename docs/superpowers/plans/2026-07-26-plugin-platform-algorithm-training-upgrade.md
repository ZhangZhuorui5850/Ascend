# 插件平台与算法训练升级实施记录

日期：2026-07-26

## 第一里程碑交付边界

第一里程碑实现设计中的 Phase 1，以及 Phase 2/3 中不依赖独立 Judge 基础设施的外链训练闭环。为了避免制造虚假的“在线判题”，主应用不执行用户代码，也不抓取百炼账号、题面、隐藏测试或提交记录。

## 已实现

- 受信任内置扩展静态注册表，首个扩展为 `algorithms`；
- 工作区级启用、停用、排序和服务端路由守卫；
- 扩展中心、设置入口、桌面/移动导航、命令面板和页面标题；
- 插件启用状态对推荐、工作区搜索和分析贡献生效；
- 百炼、OpenJudge、洛谷及通用 HTTP(S) 题目外链收录；
- AC/WA/CE/TLE/MLE/RE/OTHER、提示级别、信心、错因和复盘记录；
- 引导完成、独立完成、跨日稳定、未见变式迁移四级证据；
- D+1 / D+3 / D+10 / D+30 的可解释复测日期；
- 一键加入今日任务，训练时长写入带 `plugin:algorithms` 来源的核心学习记录；
- 首页到期复测推荐、分析页插件证据、全局搜索和工作区导出；
- 工作区隔离、停用保留数据、危险 URL 拒绝和迁移契约测试；
- 响应式审计覆盖扩展中心与算法训练页。

## 第二里程碑已追加

- 受许可的 Ascend 原创托管题目录、公开样例、隐藏测试引用、C++17/Python 3 起始代码与 L1-L4 提示梯；
- 四步训练工作区：题目、思路、代码、结果；服务端强制正式提交前思路和信心证据；
- 加密跨设备草稿、AES-256-GCM workspace/AAD 绑定、密钥版本与轮换窗口、源码体积和保留期限；
- 样例运行和正式评测分离；样例不进入学习指标，Judge 故障不记为学生错误；
- 独立 Judge Gateway 参考实现：Bearer、幂等、异步轮询、批量用例、语言白名单、并发/日配额、熔断与有限反馈；
- 隐藏输入、隐藏期望输出和隐藏 stdout 不返回浏览器、应用或 Agent；
- 正式提交、复测计划、来源任务、有效学习时长、结构化复盘、聚合错误案例和核心错题本形成闭环；
- 迁移证据显式关联“已独立 AC 的来源题 → 共享技能的变式题”，禁止仅凭用户选择训练类型生成迁移结论；
- 首次独立通过、7–20 天/21+ 天保持、未见变式迁移、掌握复发、Brier 信心校准、有效时长和 Gateway 延迟指标；
- 数据导出包含题源、提交、有限反馈、复盘、复测、错误案例和解密可用的保留源码，但排除 provider secret 与密文材料；
- `algorithm.*` 统一 Agent 操作已开放给题目、外部结果、提示、复盘和错误案例；不向 Agent 暴露隐藏测试或源码读取；
- 独立 Gateway Compose 样板、环境变量和 Worker 隔离上线门禁。
- Gateway 与主应用均在流读取阶段限制上游响应体，题目语言采用固定白名单，Gateway token 至少 32 字节。

## 仍未宣称完成

- 生产在线 Judge 尚未部署或连接；页面在配置缺失时明确显示不可用；
- 真实恶意代码 Worker 的死循环、fork bomb、超量输出、非法 syscall、逃逸和容量压测必须在独立 VM 完成；
- 百炼/OpenJudge 官方只读同步或提交回调；在正式 API、授权和版权边界未确认前长期保持外链记录模式；
- 本机真实浏览器判题链 E2E 因执行环境拒绝回环端口监听而未运行；脚本已提供为 `npm run audit:judge-chain`；
- 真实 iPhone Safari/PWA、平板和生产网络环境仍需验收。

## 第三里程碑已追加

- 30 道 Ascend 原创、CC0-1.0 托管题，foundation 18 / standard 12；
- 180 个确定性测试用例，其中 60 个公开、120 个隐藏；目录与 Gateway 由同一夹具生成并做同步测试；
- 每题至少 2 个公开样例、6 个总用例、C++17/Python 3 起始代码、L1–L4 提示和迁移家族；
- 用户明确同意申请、管理员逐工作区批准/暂停、服务端提交/轮询强制准入；
- 管理员聚合试点看板；少于 5 个实际提交工作区时抑制跨工作区学习结果；
- 5–20 人分阶段试点方案、指标合同、停止规则与每日/每周运行流程；
- 固定 Judge0 1.13.1 的完整隔离 staging Compose、最小权限 secret 分配、Ubuntu 22.04/cgroup v1 主机预检和运行时证据脚本；
- 30 题托管编辑器响应式脚本、完整 Judge 链审计与隔离攻击审计脚本；
- 本地全量验证达到 74 个测试文件、461 项测试；最终数字以完成度审计报告为准。

## 生产开放在线判题前的门禁

1. 确认首批语言、用户群、题源授权和代码保留策略；
2. 确认百炼/OpenJudge 的正式 API 与授权边界，不以抓取替代；
3. 在独立服务部署 Judge，Worker 不挂载 Ascend 数据卷或密钥，并默认禁止公网出站；
4. 覆盖死循环、fork bomb、超量输出、非法 syscall、队列满、超时和重试幂等测试；
5. 通过手机、平板、桌面关键流程、真实设备 PWA 验证与生产容量压测。

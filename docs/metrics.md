# Ascend 指标口径

更新日期：2026-07-25

## 学习、执行与整理记录

Ascend 将行为分为三层，避免用打卡或整理动作冒充学习结果。

| 层级 | 当前纳入事件 | 可用于 |
|---|---|---|
| 学习记录 | 学习活动、复习评分、错题记录、模考 | 有学习记录的天数、连续学习天数 |
| 执行记录 | 任务完成 | 计划兑现、任务完成率 |
| 整理记录 | 资料上传及后续整理动作 | 资料处理进度 |

## 当前指标

### 有学习记录的天数

[COMPUTED] 在指定统计窗口内，至少有一条学习活动、复习评分、错题记录或模考的去重日期数。

任务完成和资料上传不计入该指标。

### 连续学习天数

[COMPUTED] 使用与“有学习记录的天数”相同的事件集合，从今天开始向前计算连续日期；如果今天尚无学习记录，则允许从昨天开始。

该指标只证明系统中存在相关记录，不等同于学习质量、有效投入或知识掌握的证据。

### 专注分钟

[COMPUTED] 仅汇总 `study_sessions.duration_minutes`。复习、模考和任务的预计时长不会被推算为实际专注时间。

### 有作答证据的复习与回炉

[COMPUTED] `review_events.attempt_mode` 为 `typed`、`paper` 或 `oral`，且保存了 0–3 的揭晓前信心。草稿模式必须同时保存非空 `attempt_text`。

旧记录与未升级调用明确保存为 `attempt_mode='unknown'`，不计入作答证据覆盖率。覆盖率分母是同期全部知识点复习与错题回炉事件，分子是其中具备上述字段的事件。

该指标能证明用户在揭晓前声明并记录了一次尝试，但仍不等于客观正确率。揭晓后 0–3 结果仍包含用户自评成分。

### 主观信心与系统证据状态

- `knowledge_points.self_confidence`：用户可手工设置的 0–100 主观信心，可为空；
- `knowledge_points.mastery`：由复习、错题等系统规则更新的内部证据指数，只用于排期、状态和风险排序；
- UI 默认用“样本不足 / 仅有历史评分 / 需要巩固 / 初步稳定 / 证据较稳定”等定性状态展示系统证据，不把内部指数冒充为精确掌握率。

### 任务完成证据

[COMPUTED] `day_tasks.done=1` 只证明任务被标记为完成。若同时存在 `actual_minutes`、`completion_output`、`verification_method` 或 `verification_result`，才标记为“有完成证据”。

任务的 `actual_minutes` 是用户补记的执行证据，本身不自动并入“专注分钟”。只有用户明确选择“同时记入学习活动”（Agent 侧为 `recordAsStudy=true`）时，系统才创建或更新一条带 `task_id` 的 `study_sessions`，该时长才进入专注分钟。`completion_output` 和验证结果仍不自动证明答案正确或知识保持。诊断生成的任务通过 `source_type/source_id` 追溯来源，并可通过 `knowledge_point_id` 连接到学习对象。

### 日历周目标与容量

[COMPUTED] 周目标使用设置中的 `weekly_minutes`，边界是 ISO 日历周（周一至周日），不与分析页的滚动 7 天窗口混用：

- 已学习：本日历周 `study_sessions.duration_minutes`；
- 已排未完成：今天至本周日、尚未完成任务的 `estimated_minutes`；
- 尚未分配：`max(0, 周目标 - 已学习 - 已排未完成)`；
- 超载：`max(0, 已学习 + 已排未完成 - 周目标)`；
- 本周较早日期仍未完成的任务单独显示为过期任务，不计入未来已分配容量。

容量草案把尚未分配分钟以 30 分钟块分配到今天至周日负载较低的日期，只用于提示，不自动创建、移动或完成任务。预计分钟仍不是实际学习证据。

### 结果与过程质量信号

分析页把以下信号放在投入指标之前，并始终显示样本量：

- 7 天延迟提取：最近 90 天有真实尝试证据的知识点复习，且与同知识点上一条有证据复习间隔至少 7 天；`score >= 2` 记为成功；
- 30 天长期提取：同上，但间隔至少 30 天；
- 无提示错题重做：最近 30 天 `event_type='mistake_reattempt'` 且有尝试证据的事件；
- 信心—结果偏差：最近 30 天 `abs(pre_confidence - score)` 的平均值，范围 0–3，越低表示揭晓前信心与揭晓后自评越接近；
- 积压龄：当前到期知识点与未毕业错题的逾期天数，展示最近秩 P50 / P90；
- 训练后复测覆盖：最近 90 天带来源、知识点和完成证据的任务中，在 `done_at` 之后出现同知识点有尝试证据复习/回炉，或存在由该任务派生且已记录结构化结论的短复测的比例。

这些统计不能证明客观正确或因果改善：`score` 仍是用户核对答案后的自评；短复测的 `verification_outcome` 也是用户核对后的结构化判断。训练后复测只证明存在后续验证记录，不声称该任务造成了结果变化。少于 5 个样本只展示，不生成强结论。

## 运行质量指标

### 真实用户 Web Vitals

[COMPUTED] 已登录页面通过 Next.js 16 的 `useReportWebVitals` 上报 LCP、INP、CLS、TTFB、FCP 和 FID。管理员概览展示最近 7 天 LCP / INP / TTFB p75、样本量，以及按规范化路由聚合的 TTFB p75。

- 动态日期、科目和管理员用户路径只保存为 `/day/:date`、`/subjects/:id`、`/admin/users/:id` 等模板；
- 未知路径统一保存为 `/_other`，不保存查询参数；
- metric id 先做 SHA-256，再用于同一指标更新去重；
- 不保存用户 ID、邮箱、IP、User-Agent 或页面内容；
- 明细保留 30 天，低样本只作诊断线索，不代表全体设备。

### 失败趋势

[COMPUTED] 登录、上传、离线补传、Server Action 和 MCP 失败只按 UTC 小时、事件类型和固定代码 scope 聚合计数。管理员概览比较近 24 小时和前 24 小时；聚合桶保留 90 天。错误正文、账号、IP、输入值和资源 ID 不进入该表。

### 慢 SQLite 查询

[COMPUTED] 运行时包装同步 prepared statement 的 `get`、`all` 和 `run`；超过阈值的查询向 stderr 输出结构化 warning。默认阈值为 20 ms，可用 `ZGCA_SLOW_QUERY_MS` 调整。日志只包含耗时、调用方法、SQL SHA-256 短指纹、首个 SQL 动词和表名，不包含 SQL 参数或返回值。

## 暂不支持的结论

[KNOWN] 当前事件能够证明用户记录了学习或作答行为，但不能单独证明答案客观正确或知识已经长期保持。更强结论还需要可评分题目、延迟复测与足够样本。

# 算法训练小规模试点运行方案

日期：2026-07-26  
状态：产品准入与指标代码已实现；独立 Judge 基础设施、攻击审计和真实设备验收尚未完成。

## 1. 目的与边界

本试点不是为了证明“使用 Ascend 会提高算法成绩”，而是依次回答三个更窄的问题：

1. **安全与稳定性**：不可信代码能否始终留在独立 Worker 边界内，主应用是否能在
   Judge 故障时继续浏览题目、使用提示和保存加密草稿；
2. **产品可用性**：用户能否从读题、写计划、编码、样例、正式评测到复盘完整走通；
3. **学习证据可解释性**：首次独立完成、延迟复测、陌生变式迁移、错误复发和
   信心校准数据是否足以支持后续产品决策。

试点数据只能作描述性证据。没有随机分组、可比基线和足够样本前，不作教学因果声明。

## 2. 准入流程

状态机固定为：

```text
未申请 -> 用户明确同意并申请 -> 管理员批准 -> 可在线评测
                                \-> 暂停 -> 用户可重新申请
```

- 启用算法扩展不等于加入在线评测试点；
- 用户必须勾选说明，系统记录同意版本和时间；
- 管理员逐工作区批准并指定批次；
- 生产设置 `ASCEND_JUDGE_PILOT_REQUIRED=true` 后，服务端提交和轮询入口都要求
  `approved`，不能靠修改浏览器状态绕过；
- 暂停不删除题目、草稿、提示和既有学习证据；
- 所有申请、批准、暂停写入审计日志，摘要不含源码、邮箱或题目内容。

## 3. 分阶段规模

| 阶段 | 规模 | 建议时长 | 进入条件 | 退出条件 |
| --- | ---: | ---: | --- | --- |
| 0. 内部安全验收 | 2–3 个内部账号 | 2–3 天 | 独立主机、TLS、配额就绪 | 攻击矩阵全通过 |
| 1. 可用性试点 | 5–8 人 | 7 天 | 手机/平板/桌面/PWA 冒烟通过 | 无 P0/P1 安全或数据丢失问题 |
| 2. 学习流程试点 | 10–20 人 | 14–28 天 | 阶段 1 稳定、支持流程就绪 | 获得延迟复测与迁移样本 |

纳入条件：账号正常、算法扩展已启用、明确同意、能使用 C++17 或 Python 3、
愿意完成至少 3 次训练与 1 次延迟复测。排除条件：需要运行网络程序、
交互题、特殊判题、文件 I/O 或当前目录之外语言的用户。

## 4. 题目分配

- 起始诊断：3 道 foundation，覆盖整数处理、数组扫描、字符串；
- 主训练：每次 1 道来源题 + 1 道同构变式，先不显示迁移关系；
- 延迟复测：来源题在 7–20 天窗口复测；
- 陌生变式：至少完成一个来源题家族后，分配同技能但不同表面结构的题；
- 每位用户不要求做完 30 题，防止题量成为坚持性混杂因素；
- 不复制百炼/OpenJudge 题面或测试。第三方题保持外链与用户记录模式。

## 5. 指标合同

### 安全与可靠性

- Gateway 正式提交数；
- 基础设施失败数：`JE`、`CANCELLED`、`RETRYABLE_ERROR`；
- 创建请求 P50/P95 延迟；
- 攻击探针后健康检查通过率；
- 主应用数据卷、网络和进程边界违规数，目标必须为 0。

### 产品可用性

- 获批工作区数、发生正式提交的工作区数；
- 从首次打开托管题到首次正式提交的完成率；
- 草稿恢复成功、重复提交幂等、轮询恢复与复盘完成情况；
- 手机、平板、桌面和 PWA 各自的阻断问题数。

### 学习描述指标

- 首次尝试独立 AC；
- 7–20 天、21 天以上延迟复测独立 AC；
- 陌生变式独立 AC；
- 已独立完成题目的后续错误复发；
- 提交前信心的 Brier score；
- 有效作答时长中位数。

分母、时间窗和样本量必须一起显示。跨工作区学习结果至少需要 5 个实际提交工作区；
不足时管理员看板返回 `null` 并显示抑制说明。可靠性计数仍可显示，但小样本不能被解释为
稳定性已经得到证明。

## 6. 停止规则

发生任一条件立即暂停全部或受影响批次，不等待周期结束：

- Worker 能读取 Ascend 数据、访问公网/元数据地址、创建额外进程或绕过资源限制；
- 隐藏输入、期望输出、完整参考解或用户源码进入浏览器、应用日志或审计日志；
- 同一幂等操作产生无法解释的多个远端评测；
- 代码密文未按保留策略擦除，或密钥进入 Git、日志、备份包；
- Judge 故障导致主应用不可用或草稿丢失；
- 任何高严重度容器逃逸、依赖漏洞或未经授权的数据处理问题。

产品摩擦、低完成率或延迟偏高属于调查/调整条件，不自动等同安全停止条件，但必须在扩容前解决。

## 7. 每日与每周运行

每日：

1. 检查 Gateway 健康、队列、失败数和 P95；
2. 检查新申请并只批准已完成说明的账号；
3. 复核 P0/P1 反馈和源码/隐藏数据泄漏告警；
4. 若暂停，记录原因、影响批次和恢复证据。

每周：

1. 按批次查看参与、提交、延迟复测和迁移样本；
2. 审阅至少 3 个完整训练路径，不读取或导出不必要的源码；
3. 检查题目边界、提示梯和错误反馈是否误导；
4. 形成继续、修订或停止决定，并明确样本限制。

## 8. 上线前剩余证据

- 隔离主机上完成 `npm run audit:judge-isolation`；
- 用正式目标架构解析基础镜像 digest，生成 SBOM 并完成漏洞扫描；
- 运行 `npm run audit:judge-chain` 留下登录、启用、样例、正式 AC、复盘和数据库证据；
- 在 390×844、768×1024、1440×900 及真实 iPhone Safari/PWA 上完成交互验收；
- 先以内部账号完成阶段 0，再批准真实用户。

在这些证据完成前，代码具备试点治理能力，但不能宣称在线 Judge 已生产可用。
